# Αρχιτεκτονική Προηγμένων Υπολογιστών - Εργαστήριο 1
###  Εργαστήριο Β - Ομάδα 6:
* Χατζηιορδάνου Ελισσάβετ 8269 
* Πετρίδη Βασιλική 8602    
1) Ανοίγοντας το αρχείο starter_se.py βλέπουμε τις βασικές παραμέτρους by default:
* Cache line size: 64B
* CPU model: atomic
* CPU Frequency: 1 GHz
* Number of CPU cores: 1
* Memory type: DDR3_1600_8x8 (1600MHz η συχνότητα λειτουργίας)
* Number of memory channels: 2
* Number of memory ranks per channel: None
* Physical memory size: 2GB

Το συγκεκριμένο αρχείο μας υποδεικνύει πως μπορούμε να αλλάξουμε τις διάφορες παραμέτρους:

Έτσι, αν θέλουμε να αλλάξουμε τη συχνότητα λειτουργίας αρκεί να χρησιμοποιήσουμε το flag --cpu-freq και να θέσουμε την επιθυμητή συχνότητα
π.χ --cpu-freq="4GHz"

2) Ανοίγοντας το αρχείο stats.txt:
* sim_seconds = 0.000035 (ο αριθμός των δευτερολέπτων που χρειάστηκαν για την προσομοίωση)
* sim_insts = 5027 (ο αριθμός των εντολών)
* host_inst_rate = 93461 (ο αριθμός εντολών ανά δευτερόλεπτο)

(για cpu="minor" και cpu-freq="1GHz")

3) Από το αρχείο stats.txt:
```
system.cpu_cluster.cpus.icache.overall_misses::total = 327 (IL1.miss_num)
system.cpu_cluster.cpus.dcache.overall_misses::total = 177 (DL1.miss_num)
system.cpu_cluster.l2.overall_misses::total = 474 (L2.miss_num)
sim_insts = 5027 (Total_Inst_num)
```
Οπότε, αντικαθιστώντας κατάλληλα στον τύπο προκύπτει CPI = 6.316

4)
**SimpleCPU**: Είναι ένα απόλυτα λειτουργικό, in-order μοντέλο καταλλήλο για περιπτώσεις που δεν είναι απαραίτητο ένα λεπτομερές μοντέλο, όπως τον έλεγχο για τη σωστή λειτουργία ενός προγράμματος. Διακρίνεται σε τρείς κατηγορίες:
* **BasicSimpleCPU**: Καθορίζει συναρτήσεις που έχουν σχέση με τον έλεγχο για interrupts, το χειρισμό ρυθμίσεων και ενεργειών πριν και μετά την εκτέλεση, και την προώθηση του PC στην επόμενη εντολή. Αποτελεί τη βάση για τις δύο επόμενες κατηγορίες, παρ'όλα αυτά δεν μπορεί να τρέξει μόνος του.
* **AtomicSimpleCPU**: Απορρέει από το BaseSimpleCPU και χρησιμοποιεί πρόσβαση ατομικής μνήμης. Χρησιμοποιεί, δηλαδή, τις προσεγγίσεις από τις προσβάσεις στην ατομική μνήμη και υπολογίζει προσεγγιστικά το συνολικό χρόνο πρόσβασης της cache. Υλοποιεί συναρτήσεις για εγγραφή και ανάγνωση μνήμης και συνδέει CPU και cache.
* **TimingSimpleCPU**: Απορρέει, επίσης, από το BaseSimpleCPU και χρησιμοποιεί πρόσβαση στη μνήμη χρονισμού. Καθυστερεί τις προσβάσεις στην cache και περιμένει την απόκριση του συστήματος μνήμης, πριν προχωρήσει στην εκτέλεση εντολών. Υλοποιεί το ίδιο σετ συναρτήσεων με την AtomicSimple και συνδέει CPU και cache.

**MinorCPU**: Έχει τέσσερα συγκεκριμένα στάδια διοχέτευσης (Fetch1, Fetch2, Decode, Execute), καθώς και διαμορφώσιμες δομές δεδομένων και διαμορφώσιμη συμπεριφορά εκτέλεσης. Χρησιμοποιείται για τη μοντελοποίηση επεξεργαστών με αυστηρή σειρά εκτέλεσης εντολών και για την οπτικοποίηση της θέσης κάθε εντολής στο pipeline.

a)
* Για το μοντέλο TimingSimpleCPU εκτελώ:
```
./build/ARM/gem5.opt -d myprog_result configs/example/se.py --cpu-type=TimingSimpleCPU --caches -c myprog_arm
```
και βλέπω από το stats.txt ότι έχω χρόνο εκτέλεσης sim_seconds = 0.000047
* Για το μοντέλο MinorCPU εκτελώ:
```
./build/ARM/gem5.opt -d myprog_result configs/example/se.py --cpu-type=MinorCPU --caches -c myprog_arm
```
και έχω sim_seconds = 0.000041.
Βλέπουμε ότι ο MinorCPU είναι ελάχιστα πιο γρήγορος από τον TimingSimpleCPU (default συχνότητα φαίνεται να είναι τα 2GHz)

b)
Αλλάζοντας, αρχικά, τη συχνότητα λειτουργίας στο TimingSimpleCPU, για:
* 1GHz: sim_seconds = 0.000063
* 2GHz: sim_seconds = 0.000047
* 4GHz: sim_seconds = 0.000038 (χρησιμοποιώντας --cpu-clock=XGHz)

και στο MinorCPU:
* 1GHz: sim_seconds = 0.000049
* 2GHz: sim_seconds = 0.000041
* 4GHz: sim_seconds = 0.000037

Με βάση τη διαφορά στους χρόνους, μεγαλύτερη ευαισθησία στην αλλαγή της συχνότητας φαίνεται να έχει ο TimingSimpleCPU.

Εξετάζοντας τώρα για τα μοντέλα DDR3_1600_8x8 και DDR4_2400_8x8 και κρατώντας σταθερή τη συχνότητα ρολογιού στα 1GHz:

Για TimingSimpleCPU:
* DDR3_1600_8x8: sim_seconds = 0.000063
* DDR4_2400_8x8: sim_seconds = 0.000063

Για MinorCPU:
* DDR3_1600_8x8: sim_seconds = 0.000049
* DDR4_1600_8x8: sim_seconds = 0.000048

Με βάση αυτούς τους δύο τύπους μνήμης, ο χρόνος εκτέλεσης φαίνεται να είναι πρακτικά αμετάβλητος. Αυτό, οφείλεται, εν μέρει, στο ίδιο το πρόγραμμα της C, μιας και απαιτεί ελάχιστο αριθμό προσπελάσεων στην κύρια μνήμη, άρα δεν υπάρχει ιδιαίτερη μεταβολή στο χρόνο εκτέλεσης. Τα συστήματα με τα οποία ασχολούμαστε, όμως, είναι μικρού βεληνεκούς, οπότε οποιαδήποτε μεταβολή στο χρόνο είναι αμελητέα. Σε ένα μεγαλύτερο σύστημα, οι διαφορές θα ήταν σαφώς πιο ευδιάκριτες.
